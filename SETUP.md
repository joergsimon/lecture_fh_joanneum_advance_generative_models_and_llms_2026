# Installation and local setup

This guide starts from a new computer. You do not need the lecturer's Conda
environment and should not copy environment names from screenshots or speaker
notes.

## 1. Install the prerequisites

You need Git and one Python environment manager. The recommended manager is
[`uv`](https://docs.astral.sh/uv/), because it can install Python 3.11 for you.

### macOS

With Homebrew:

```bash
brew install git uv
```

### Windows

In PowerShell:

```powershell
winget install --id Git.Git -e
winget install --id astral-sh.uv -e
```

Open a new terminal after installation so that `git` and `uv` are on `PATH`.

### Linux

Install Git with the package manager of your distribution. Then install `uv`
using one of the methods in the
[official installation guide](https://docs.astral.sh/uv/getting-started/installation/).
For example, the official standalone installer is:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

If your institution blocks installation scripts, use Conda/Miniforge or ask
the lecturer for the managed lab environment instead.

Verify the tools:

```bash
git --version
uv --version
```

## 2. Download the course repository

```bash
git clone https://github.com/joergsimon/lecture_fh_joanneum_advance_generative_models_and_llms_2026.git
cd lecture_fh_joanneum_advance_generative_models_and_llms_2026
```

To update an existing clone later:

```bash
git pull --ff-only
```

## 3. Baseline

- Python 3.11
- Git
- `uv` (recommended), Conda/Miniforge, or the standard Python virtual environment
- Optional: Ollama or LM Studio for local language-model inference

No paid API is required. Python is the supported training and fine-tuning baseline. Python or TypeScript may be used for inference and harness work when the required interfaces, traces, and evaluations remain equivalent.

## 4. Lecture 2 environment: recommended `uv` route

```bash
cd lectures/lecture_02/demos
uv venv --python 3.11
source .venv/bin/activate          # macOS or Linux
# Windows PowerShell: .venv\Scripts\Activate.ps1
uv pip install -r requirements.txt
python -m jupyter lab
```

`requirements.txt` is the portable default. `requirements-lock.txt` records
the exact validated versions and is useful for reproduction when the platform
supports every pinned package.

Activation is optional. Without activation, replace `python` with
`.venv/bin/python` on macOS/Linux or `.venv\Scripts\python.exe` on Windows.

## 5. Alternative: Conda or Miniforge

If Conda or Miniforge is already installed:

```bash
cd lectures/lecture_02/demos
conda env create -f environment.yml
conda activate lecture2-generative-demos
python -m jupyter lab
```

The environment name is created by `environment.yml`; it is not a private
lecturer environment.

## 6. Alternative: standard Python `venv`

Install Python 3.11 first, then run:

```bash
cd lectures/lecture_02/demos
python3.11 -m venv .venv
source .venv/bin/activate          # macOS or Linux
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m jupyter lab
```

Windows PowerShell equivalents:

```powershell
py -3.11 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m jupyter lab
```

## 7. Verify the installation

Verify the environment:

```bash
python -c "import torch, torchvision, numpy, matplotlib; print('PyTorch', torch.__version__); print('CUDA', torch.cuda.is_available()); print('MPS', torch.backends.mps.is_available())"
python tools/verify_demos.py
```

The expected device line is one of:

- `CUDA True` for a working NVIDIA/PyTorch CUDA installation;
- `MPS True` on a supported Apple Silicon Mac;
- both `False` for CPU execution, which is sufficient for the core notebook
  pathway and the supplied checkpoints.

Open `01_autoregressive_4_pixel.ipynb` first and run all cells. It is the
smallest end-to-end test and does not download a dataset.

## 8. Hardware-specific notes

### NVIDIA CUDA

Do not install a random CUDA toolkit only because `CUDA False` is printed.
First confirm that the machine has a supported NVIDIA GPU and driver, then use
the command generated by the official
[PyTorch installation selector](https://docs.pytorch.org/get-started/locally/)
for the installed driver and operating system. Re-run the verification command
afterwards.

### Apple Silicon

The notebooks use PyTorch's `mps` backend automatically when it is available.
MLX is not required for Lecture 2. If an operation is unsupported on MPS, the
notebook instructions provide a CPU-safe path.

### CPU-only computers

Use the prepared checkpoints and fallbacks. Notebooks 1--5 are designed to be
usable on CPU. For PixelCNN, use the smoke profile rather than full training:

```bash
LECTURE2_QUICK=1 python -m jupyter lab       # macOS or Linux
$env:LECTURE2_QUICK=1; python -m jupyter lab # Windows PowerShell
```

## 9. Data and network requirements

The repository contains the compact VAE and diffusion checkpoints. Notebooks
1--5 need no network after installation. The PixelCNN notebook downloads
Fashion-MNIST once unless it is already present under
`lectures/lecture_02/demos/data/FashionMNIST/`.

Downloaded datasets, executed notebooks, virtual environments, and temporary
training checkpoints are excluded by `.gitignore`.

## 10. Lightweight replay paths

These exercises use the Python standard library. Return to the repository root
first if you followed the Lecture 2 commands above:

```bash
cd ../../..
```

Then run:

```bash
python assignments/mission1_sampling/run_sampling.py --replay
python labs/lecture3_transformer_lab/transformer_lab.py
python lectures/lecture_04/practical/scout_retrieval_lab.py
python assignments/mission3_change_one_thing/evaluate.py
python assignments/mission4_scout_on_a_leash/harness.py --variant controlled
python assignments/mission4_scout_on_a_leash/evaluate_replays.py
```

## 11. Local language models

If an exercise uses Ollama or LM Studio, record the exact model identifier, quantisation, runtime version, and decoding settings. Use a small quantised model that fits the available computer. Supplied replay outputs and checkpoints provide the low-compute fallback.

## 12. Repository hygiene

Do not commit downloaded datasets, large model weights, `.env` files, credentials, private data, or notebook autosaves. Run the repository check before committing:

```bash
python scripts/check_repository.py
```
